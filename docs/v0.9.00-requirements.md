# Abyss Alchemy v0.9.00 変更仕様要件

## 1. 文書の位置づけ

- 対象バージョン: `0.9.00`
- コードネーム（仮）: **深淵侵食 / Abyssal Erosion**
- 本書は実装前のプロダクト・ゲームデザイン要件を定義する。
- 数値は初回プレイテスト用の基準値であり、実装時は `config.js` の定数として分離する。

## 2. 背景と課題

20層前後では、変異「物質変換」「スカベンジャー」「桃の幸運」や完成イベントからのアイテム供給により、多くの消費アイテムが所持上限3個へ到達する。強力なアイテムを数個使うだけで階層を突破でき、以下の問題が発生している。

1. パズルを解く緊張感と、HP・プレッシャーを管理する必要性が薄れる。
2. ショップでアイテムを買う理由がなくなる。
3. エッセンスが余り、通貨としての意思決定が消える。
4. アイテム獲得系の変異・イベントが、上限到達後は実質的な外れになる。

## 3. 設計目標

1. 深層ほど「持ち込めば必ず使える」という保証を弱め、消耗品を備蓄ではなく運用する資源へ戻す。
2. エッセンスに、購入・Undo・回復とは異なる継続的な使途を設ける。
3. プレイヤーが「何を守り、何を危険にさらすか」を選べるようにする。
4. 深淵に近づく不穏さを、侵食・蝕み・汚染・腐敗・風化・消滅という語彙と演出で表現する。
5. ランダム要素は計画を揺さぶるが、単独ではゲームオーバーや詰みを発生させない。

## 4. 非目標

- アイテムを使う行為そのものを弱く、または不快にすること。
- 全階層で常にアイテムが壊れるゲームにすること。
- プレイヤーへ見えない確率だけで結果を決めること。
- エッセンス支払いを事実上必須の税にすること。
- 既存の異常階層・ボス攻撃を置き換えること。侵食はそれらと共存する恒常的な深度システムとする。

## 5. 中核仕様: 深淵侵食

### 5.1 侵食強度

階層開始時に、その階層の **侵食強度** を決定する。侵食は1～9層では発生せず、10層から予告のみ開始し、11層以降で実害が発生する。

| 階層 | 侵食段階 | 基礎侵食率 | 階層開始時の対象数 | 使用時の不発率上限 |
|---|---:|---:|---:|---:|
| 1～9 | 0: 静穏 | 0% | 0 | 0% |
| 10 | 予兆 | 0% | 0 | 0% |
| 11～15 | 1: 風化 | 40% | 最大1枠 | 0% |
| 16～20 | 2: 蝕み | 70% | 最大1枠 | 5% |
| 21～25 | 3: 汚染 | 75% | 最大2枠 | 8% |
| 26～30 | 4: 腐敗 | 100% | 最大2枠 | 10% |
| 31以降 | 5: 深淵侵食 | 100% | 最大3枠 | 12% |
| 40以降 | 6: 全域侵食 | 100% | 未保護の全所持枠 | 15% |

- 「枠」はアイテムID単位を指す。同種3個を所持していても一度の判定対象は1枠である。
- 基礎侵食率は対象枠が状態異常を受ける確率であり、対象数すべてが必ず被害を受ける意味ではない。
- 侵食対象は65%の確率で風化・汚染中の枠を優先し、放置した状態異常が腐敗まで進行しやすくする。
- 31～39層の不発率は12%、40層以降は15%とする。40層以降は未保護の全所持枠を侵食対象にする。
- ボス階層では階層開始時の侵食判定を行わない。一時支給品も侵食対象外とする。
- 新規獲得したアイテムは、獲得した階層中は侵食対象外とする。

### 5.2 アイテム状態

各アイテム枠は次のいずれかの状態を持つ。

| 状態 | 効果 | 回復方法 |
|---|---|---|
| 正常 | 現行どおり使用可能 | 不要 |
| 風化 | 使用時に不発判定が発生する | ショップで8～20エッセンス、または使用して消費 |
| 汚染 | 次の階層移動時に1個消滅する | ショップで12～28エッセンスを払い風化へ戻す |
| 腐敗 | 使用不能。次の階層移動時に同種の所持スタックを全消失する | ショップで17～37エッセンスを払い汚染へ戻す |

- 状態は `正常 → 風化 → 汚染 → 腐敗` の順に最大1段階だけ進行する。一度の侵食判定で複数段階悪化しない。
- 腐敗による消滅は階層終了時に明示的に予告し、次の階層へ進む前にショップで浄化・保護・使用判断を行える。
- 汚染による消滅は1回の階層移動で最大1個とする。腐敗がある場合は腐敗を優先し、選ばれた同種スタックを全消失させる。
- 腐敗で1個消滅した後、同種の残存在庫は汚染へ1段階戻す。同じスタックが対策不能なまま連続消滅することを防ぐ。
- 所持数1個の枠は、他に所持数2個以上の候補がある限り腐敗・消滅の対象に選ばない。
- 回復アイテムしか残っていない場合、その最後の1個は消滅対象外とする。

### 5.3 使用時の不発

- 不発判定は「風化」状態の通常在庫にのみ適用する。
- 対象選択型・二段階型は、対象を確定する直前に判定する。キャンセル操作では判定しない。
- 不発時は効果を発動せず、アイテムを消費しない。代わりにそのアイテムの風化状態を解除し、プレッシャーを2加算する。
- 不発でプレッシャー上限へ到達する場合、その判定では上限直前に留める。不発単独でHPダメージを発生させない。
- 現在の不発率は、アイテムカードと使用確認表示に数値で明記する。
- Recyclerによる「消費しない」判定は、効果が成功した後にのみ行う。不発とは別判定にしない。

この仕様により、不発は手番と圧力の損失になる一方、アイテムそのものをランダムに失わず、同じアイテムが連続で不発することもない。

## 6. エッセンス用途: 封蝋保護と浄化

### 6.1 階層間ショップへの追加

ショップに **侵食対策** パネルを常設する。

1. **封蝋保護**: 任意のアイテム枠を次の1階層だけ侵食から保護する。
2. **浄化**: 風化・汚染・腐敗を1段階戻す。価格は侵食段階に応じて上昇し、1ショップにつき合計2回まで利用できる。
3. **一括応急処置**: すべての腐敗を汚染へ1段階戻す。

### 6.2 初期価格

| サービス | 価格 | 制約 |
|---|---:|---|
| 封蝋保護 1枠 | 段階別4 / 6 / 8 / 10 / 12 | 1階層につき2枠まで |
| 風化の浄化 | 8～20 | 正常へ1段階戻す。侵食段階で上昇 |
| 汚染の浄化 | 12～28 | 風化へ1段階戻す。侵食段階で上昇 |
| 腐敗の浄化 | 17～37 | 汚染へ1段階戻す。侵食段階で上昇 |
| 一括応急処置 | 8 | 1ショップにつき1回 |

- 侵食対策サービスには通常の階層価格倍率を適用しない。
- 変異「交渉術」の割引は半分の効果で適用し、最低価格は1とする。
- 保護はアイテム個数ではなくアイテム枠に付く。同種を複数持つ価値を維持する。
- 支払わなくても、腐敗品を先に使う、危険を受け入れる、別のアイテムだけ守る、という攻略が成立しなければならない。

## 7. 深淵による体力の蝕み

ランダムな即時HP減少は採用せず、**蝕み予兆** として実装する。

- 21層以降、通常階層開始時に最大10%で蝕み予兆が付与される。
- 予兆は「この階層でプレッシャーダメージを受けた場合、追加でHP-1」と事前表示する。
- HPが2以下の場合、追加HPダメージは発生せず、代わりにエッセンス-3。エッセンスもなければプレッシャー+2（上限直前まで）へ置換する。
- 1階層につき1回だけ発動し、ボス・異常階層・禁忌ルートでは抽選しない。
- 侵食による不発を原因とするプレッシャーでは発動しない。

これによりHPへの脅威を感じさせつつ、抽選結果だけで死亡することを禁止する。

## 8. 供給過多への補助調整

侵食だけで供給量を相殺せず、獲得側にも上限到達時の価値を設ける。

- ランダムアイテム獲得で全候補が上限の場合、現行の固定エッセンス還元ではなく **残滓** を1得る。
- 残滓3個はショップで「任意の汚染を浄化」またはエッセンス5へ交換できる。
- 「物質変換」は1階層につき最大2個までとし、同じアイテムを複数生成しない。候補不足時は残滓へ変換する。
- 変異・イベント由来の獲得も、上限3を超えて増加させない。
- ショップは侵食中または所持数1以下のアイテムを優先して候補へ混ぜ、購入の意味を回復する。

## 9. 他システムとの相互作用

### 9.1 Undo

- 侵食抽選、状態悪化、消滅、不発結果はUndoで巻き戻さない。
- 乱数の引き直しを防ぐため、不発結果はアイテム使用確定時に履歴外の状態として保存する。
- 対象選択前のキャンセルはUndo扱いにせず、ペナルティもない。

### 9.2 ボス

- `temporaryInventory` は常に正常かつ保護済みとして扱う。
- 通常在庫の風化アイテムが不発した場合、ボス核露出・攻撃遅延は発生しない。
- ボス突入直前のショップでは、最低1回は侵食対策パネルを利用できる。

### 9.3 異常階層・深淵契約

- 異常階層では基礎侵食率を加算しない。複合事故を避けるため侵食対象数を1減らす（最低0）。
- 安定ルート: 基礎侵食率 x0.75。
- 危険契約: 変更なし。
- 禁忌ルート: 基礎侵食率 x1.25。ただし表の上限と消滅上限は超えない。
- 深淵注目度は侵食率へ直接加算しない。プレイヤーが危険度を予測できる状態を保つ。

### 9.4 アイテム獲得系変異

- 獲得直後保護により、得た瞬間に侵食されることを防ぐ。
- Recyclerは不発に対して発動しない。
- アイテム獲得系変異の価値は、残滓変換によって上限到達後もゼロにしない。

## 10. UI・演出要件

- HUDに侵食段階、次回判定タイミング、保護枠数を常時表示する。
- アイテムカードに状態アイコン、状態名、具体的な影響、不発率を表示する。
- 状態色は色だけに依存せず、アイコンと文言を併用する。
- 腐敗による消滅対象は階層終了前から明滅表示し、「次の降下で1個消滅」と明記する。
- 階層開始時の結果は一括サマリーで表示し、複数トーストを連打しない。
- 演出語彙は次を基準とする。
  - 低段階: 「風化した」「蝕まれている」
  - 中段階: 「汚染された」「侵食が進行」
  - 高段階: 「腐敗した」「次の降下で消滅」
- 日英両方の表示を同時に実装する。

## 11. データ・セーブ要件

0.8系セーブを維持し、`migrateV090State()` で以下を補完する。

```text
itemConditions: {}          // itemId -> normal | weathered | polluted | decayed
protectedItemIds: []        // 次階層だけ保護されるitemId
freshItemIds: []            // 現階層中のみ侵食対象外のitemId
erosionTier: 0
erosionPreview: null
decayPending: []
abyssResidue: 0
erosionStats: {
  checks: 0,
  affected: 0,
  misfires: 0,
  lostItems: 0,
  essenceSpentOnProtection: 0
}
```

- 存在しないアイテムIDの状態はロード時に破棄する。
- 所持数0になったアイテムの状態・保護・予告も削除する。
- 旧セーブの全アイテムは正常状態から開始する。
- ラン中の乱数再抽選を避けるため、次回侵食結果は階層遷移確定時に保存する。

## 12. 理不尽防止の絶対制約

以下は調整で緩和せず、実装上の不変条件とする。

1. 侵食または蝕みだけを直接原因としてHPが0にならない。
2. 侵食によって盤面の液体配置を変更しない。
3. 侵食によって空き瓶を削除・封鎖しない。
4. 汚染によるランダム消滅は最大1個。腐敗は1種類のスタック全数を消滅させるが、最後の回復アイテムは残す。
5. 一時支給品、獲得直後の品、最後の回復アイテムは消滅しない。
6. 同じアイテムが1回の不発後に再度不発することはない。
7. 被害の確率、候補、発生タイミング、回避手段を事前に確認できる。
8. ボス攻撃・異常攻撃・腐敗消滅が同じ階層開始処理で同時発生しない。
9. 候補が安全条件を満たさない場合、侵食判定は何も起こさず終了する。
10. 侵食処理後も通常操作だけで解ける盤面であることをデッドロック検査で保証する。

## 13. 受け入れ条件

### 機能

- 11、16、21、26、31層で表どおりの段階・上限が適用される。
- 保護した枠は次の1階層の全侵食判定から除外され、その後保護が解除される。
- 風化アイテムの不発時に、効果・消費・ボス遅延が発生しない。
- 汚染品は次回降下で最大1個、腐敗品は次回降下で選ばれた同種スタック全数が消滅する。
- Undo、セーブ、ロード、再読込で侵食結果を引き直せない。
- 0.8系の既存セーブをエラーなく開始できる。

### バランス（通常プレイ100ランの計測目標）

- 20層到達時、全消費アイテム枠が上限のランを20%未満にする。
- 16～25層で、獲得エッセンスの25～45%が購入・Undo・回復・侵食対策のいずれかへ消費される。
- 侵食対策への支出は総支出の15～35%に収まり、必須税にならない。
- 侵食を直接原因とするゲームオーバーは0件。
- 1階層で2個以上のランダム消滅は0件。
- 16～25層のクリア時アイテム使用数の中央値は1～2個とする。
- 20層ボスの初見到達者が、侵食だけを理由に支給品以外を一切使えない状態にならない。

### プレイ感

- テスターの80%以上が、被害発生前に回避方法を認識できる。
- 「結果を知らずに即死した」「対策不能だった」という報告を重大不具合として扱う。
- 「守る品を選ぶ」「腐敗前に使う」「浄化せず買い直す」の3方針がいずれも有効である。

## 14. テレメトリ要件

外部送信を行わない現状では、デバッグパネルおよび探索終了結果に次を記録・表示する。

- 階層別の侵食抽選数・状態悪化数
- アイテム別の不発数・消滅数
- 保護・浄化に使ったエッセンス
- 階層開始時／終了時の総アイテム数
- アイテム獲得数と残滓変換数
- 侵食予兆中の被ダメージと死亡原因

## 15. 実装フェーズ

### Phase 1: 必須（0.9.00）

- 侵食段階、アイテム状態、封蝋保護、浄化
- 風化・汚染・腐敗・予告付き消滅
- 不発の安全制約
- 獲得直後保護、ボス支給品除外
- セーブ移行、Undo耐性、デバッグ統計
- UI・日英翻訳

### Phase 2: 初回バランス更新候補（0.9.01以降）

- 蝕み予兆
- 残滓と交換メニュー
- 契約ごとの侵食補正
- 侵食対策に関係する新規変異・イベント

Phase 1の計測でアイテム飽和とエッセンス余剰が十分に改善した場合、Phase 2の罰要素は追加せず、残滓など選択肢を増やす要素だけを採用する。

## 16. 未採用案と理由

- **所持アイテムを無予告で即時消滅**: 計画不能であり、ボス直前の敗因になり得るため不採用。
- **使用成功率を深度だけで大幅低下**: アイテムUIへの信頼を壊すため、不発率12%上限・不発後浄化とする。
- **階層開始時にランダムHP減少**: 抽選だけで死亡し得るため不採用。予告付きかつ非致死の蝕みへ置換する。
- **余剰エッセンスを毎階層自動徴収**: 選択ではなく税になるため不採用。
- **所持上限を1へ低下**: 飽和時期を遅らせるだけで、獲得変異の価値や通貨余剰を解決しないため不採用。
